\chapter{System architecture}\label{ch:arch}

\section{Architectural style}
CETP is a Python library with a command-line front end, plus an offline research pipeline. It is
\emph{not} a service: there is no daemon, no database of its own, and no network listener. State is
held in three places, all plain files: the operator-signature registry
(\src{models/operator\_signature.json}), the per-pair calibration store (\src{\textasciitilde/.cetp/calibration.json}), and
an append-only telemetry log (JSON Lines). This keeps the product auditable and the runtime
dependency set empty (\src{pyproject.toml}: \texttt{dependencies = []}, \evFILE).

\begin{honest}
The figure also shows the most important structural fact about the repository: the user-facing
surfaces that exist outside the CLI (the VS Code extension and the two CI workflows that make predictions, \texttt{cetp-gate.yml} and \texttt{cetp-regression-check.yml}) call Gen-1 code only; the third workflow, \texttt{x86-operator-probe.yml}, runs the Gen-2 probe.
The newer per-operator model is reachable through \texttt{cetp predict-prod} and
\src{scripts/collection/predict_prod.py}. This is documented in the evidence pack (risk R-series) and
re-confirmed here by reading \src{gate/cetp\_gate.py}, which loads \texttt{models/*.pkl} and calls the
bottleneck-weighted formula.
\end{honest}

\section{Deployment topology}
There is no deployed service. The realistic topologies are:
\begin{enumerate}
\item \textbf{Local developer.} Installs the package (the exact command, e.g.\ \texttt{pip install -e .}, is inferred from \texttt{pyproject.toml}, not verified \evUNK); the developer runs \texttt{cetp predict-prod}
  with two EXPLAIN JSON files and two registry identifiers.
\item \textbf{Live harness.} \src{scripts/collection/predict_prod.py} connects to dev and prod
  PostgreSQL through \texttt{psycopg2}, runs \texttt{EXPLAIN} on production (no \texttt{ANALYZE}), forces
  that plan on dev using \texttt{pg\_hint\_plan}, measures, predicts, and records into the calibration
  store. It needs a database, so I did not run it (\evUNK).
\item \textbf{CI.} The Gen-1 gate workflow (\src{.github/workflows/cetp-gate.yml}) installs the pinned
  requirements and runs \src{gate/cetp\_gate.py} against a stored SLA configuration; a BLOCK verdict is
  deliberately \emph{not} a build failure (commit \texttt{ffce2ec}).
\item \textbf{Reproducibility artefact.} A \texttt{python:3.13-slim} Docker image reruns the analysis
  from committed data with no database (\src{Dockerfile}).
\end{enumerate}

\section{Design principles visible in the code}
\begin{enumerate}
\item \textbf{Refuse rather than mislead.} Several functions raise on unsafe inputs: v1 signatures,
  unreliable probes, mismatched probe scales, and uncalibrated cross-ISA prediction.
\item \textbf{Every prediction carries its own critique.} The result dictionary always contains
  \texttt{explained\_frac}, \texttt{unmapped\_frac}, a trust level and a list of warnings.
\item \textbf{Zero dependencies in the shipped path.} The pickled scikit-learn models are confined to the
  Gen-1 gate and the research scripts, because pickles are version-coupled.
\item \textbf{Provenance is a first-class artefact.} \src{models/PROVENANCE.json} records
  library versions and a \texttt{version\_mismatch: false} flag, and result generation is hash-checked
  (\cref{sec:c10}).
\end{enumerate}
