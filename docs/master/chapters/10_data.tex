\section{Schemas}
\subsection{Operator-signature registry record}
\src{models/operator\_signature.json}: object keyed by machine id; each record (v2) contains
\texttt{signature\_kind='operator\_rates\_v2'}, \texttt{machine\_id}, \texttt{client\_platform} (e.g.\ ``Darwin arm64''),
\texttt{server\_version}, \texttt{rates\_tuples\_per\_s} \{seqscan, hashjoin, sort, hashagg, nestloop, io\_seqscan, parallel\_seqscan\},
\texttt{parallel\_speedup}, \texttt{parallel\_speedup\_cv}, \texttt{parallel\_dop}, \texttt{probe\_scale}, \texttt{detail},
\texttt{noisy\_probes}, \texttt{imprecise\_probes}, \texttt{invalid\_probes}, \texttt{reliable}, \texttt{max\_cv}, \texttt{max\_median\_se}.
Constraint: records are comparable only at identical \texttt{probe\_scale} (enforced by \texttt{assert\_comparable}).

\subsection{Calibration store}
\texttt{\{"version":1, "pairs":\{"dev->prod":\{"dev","prod","dev\_arch","prod\_arch","observations":\{query\_id:\{"predicted\_scaling","actual\_scaling","recorded\_at"\}\}\}\}\}}.
Path \texttt{\textasciitilde/.cetp/calibration.json}, override \texttt{CETP\_CALIBRATION\_PATH}.

\subsection{Telemetry (JSON Lines)}
One object per prediction: \texttt{ts, query\_id, dev, prod, predicted\_ms, dev\_ms, scaling, trust, calibration, cross\_architecture, prod\_clients, actual\_ms, resolved\_at}.
\texttt{extra} keys named like \texttt{query, sql, statement, plan, filter, literals, query\_text} are refused. This guards only the \texttt{extra} dictionary: the
\texttt{query\_id} string is free text and could contain a statement if a caller passes one.

\subsection{Gen-1 conformal table}
\src{models/calibration.json} (\texttt{cetp-calibration/1}): for predictors \texttt{analytical} and \texttt{cmp\_only}, the empirical quantiles of
$\ln(y/\hat y)$ at levels 0.5, 0.8, 0.9, 0.95, 0.99 pooled over five LOMO folds, their exponentials as \texttt{multiplier}, and per-fold quantiles; plus four
\texttt{caveats} (marginal coverage, five-machine envelope, engine versions, single client).

\subsection{Evaluation outputs}
\texttt{canonical\_metrics.json} has the keys \texttt{dataset, environment, headline, scaling\_factor\_results, bootstrap\_lomo, breakdowns\_lomo,
leakage\_audit, measurement\_noise, bottleneck\_classifier\_loqo, shipped\_artifact\_consistency} (\evRUN\ read). \texttt{operator\_model\_metrics.json} is regenerated with
input hashes so a stale input cannot silently reproduce (\cref{sec:c10}).

\section{Integrity controls}
\begin{enumerate}
\item \textbf{Hash-checked inputs.} The Gen-2 evaluation records SHA-256 of each input and the test
  \texttt{test\_committed\_metrics\_were\_generated\_from\_the\_committed\_inputs} checks them.
\item \textbf{Manifest-selected grid.} After C10 the evaluation reads \texttt{grid\_manifest.json} instead of globbing the directory; a test adds extra files and
  checks the grid is unchanged (\texttt{test\_extra\_files\_in\_the\_grid\_directory\_do\_not\_change\_the\_grid}).
\item \textbf{Shipped-artifact consistency.} \texttt{canonical\_evaluation.shipped\_artifact\_consistency} (l.\,390) cross-checks the shipped models against the
  canonical dataset (\texttt{all\_consistent: true}).
\item \textbf{Provenance file.} \src{models/PROVENANCE.json} records library versions and a \texttt{version\_mismatch} flag.
\end{enumerate}
\begin{honest}
Data quality is the weakest part of the project. Raw EC2 logs are gone, the five instances were terminated, only five distinct EC2 hardware points exist, and the laptop-to-EC2
pairs combine different PostgreSQL builds and storage. The measurement-noise section of \src{canonical\_metrics.json} says it directly: 11 of 105 cells exceed 5\% CV even after discarding the cold run.
\end{honest}
