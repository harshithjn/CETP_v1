\section{Test strategy}
\begin{itemize}
\item \textbf{Specification by example.} \texttt{test\_operator\_model.py} builds small synthetic plans (helpers \texttt{plan}, \texttt{n}) so each rule has a one-screen test.
\item \textbf{Locked values.} \texttt{test\_e2e.py::TestKnownAnswerRegression} locks five predictions; its own comment says it is ``a frozen regression lock on the model's arithmetic only -- not verified against a real plan''.
\item \textbf{Refusal tests.} Every guard in \texttt{load\_rates} and \texttt{cross\_env.predict} has at least one test.
\item \textbf{Reproducibility tests.} Metrics regeneration is compared to committed files with a tolerant dictionary comparison (\texttt{\_assert\_close}) and a determinism test (second run identical).
\item \textbf{Leakage guards.} \texttt{TestLeakageGuard} asserts that the gate's feature lists contain no production-side columns.
\end{itemize}

\section{Verification beyond unit tests}
\begin{enumerate}
\item \textbf{Cross-checking by recomputation.} \evRUN\ I recomputed the pooled conformal coverage from \src{results/tier1\_conformal.csv} (\cref{sec:conformal}) and re-derived the Gen-1 and Gen-2 worked examples by hand (\cref{ch:algo,ch:workflows}).
\item \textbf{Leakage audit.} The canonical script reports each approach with a refit-per-fold classifier and with one global classifier. For the learned model the difference is 1.7\,pp (LOMO: 23.90 vs 25.62; the leaky variant is the \emph{worse} one), i.e.\ the earlier leakage did not flatter the LOMO headline \evFILE. (Under LOQO and LOMQO the leaky variant is marginally \emph{better}: 17.04 vs 17.29 and 26.56 vs 26.86.)
\item \textbf{Determinism.} \texttt{make verify-determinism}: two runs, \texttt{cmp} the outputs. Result \evPACK.
\item \textbf{Evidence audit.} The pack's C1--C16 contradictions and R1--R10 risks (\cref{app:issues}) are themselves a verification artefact.
\end{enumerate}
