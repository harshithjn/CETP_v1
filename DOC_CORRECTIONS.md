## Confirmed as implemented — safe to claim

- **Root-node-only buffer capture.** `root_buffers()` reads the root node's cumulative counts.
  Summing per-node was the bug; it is fixed in the gate and corrected in the dataset.
- **Hardware signature** = STREAM-triad bandwidth + OpenMP multi-core compute, stored per machine.
- **4-class probability output** feeding the regressor as `p_compute/p_bandwidth/p_io/p_mixed`.
- **Quantile regressors** for p50/p95/p99 with `random_state=42`.
- **Analytical estimator exists and acts as a fallback.**
- **Confidence gate semantics**: `confidence = max(0, 1 − min_distance / √2)` over normalised
  (bandwidth, compute) space, threshold 0.6. The 0.6 is a hand-set constant, not derived —
  say so.
- **Analytical weights**: mixed = `sqrt(inv_bandwidth × inv_compute)` (geometric mean), io term
  = `1/bandwidth_ratio`. Both confirmed at `gate/cetp_gate.py:68-71`. Note the io weight is
  folded in with bandwidth, which is *why* §4 shows no io improvement.
- **CI/CD gate** returns PASS / BLOCK / WARN, with WARN also on low confidence.
  `.github/workflows/` runs it on q19, q1, q18 on every push. 24 tests pass.
- **Self-calibration loop**: persist → register machine → retrain, with versioned artifacts in
  `models_online/v2/`.
- **13 features, no `prod_*` leakage** in the feature list.
- **Model registry files exist**: `models/bottleneck_classifier.pkl`,
  `models/scaling_quantile_models.pkl`, `models/hardware_signature.pkl`. Note the names differ
  from the LLD's `quantile_regressor.pkl` / `bottleneck_clf.pkl` / `hardware_signatures.json`.
